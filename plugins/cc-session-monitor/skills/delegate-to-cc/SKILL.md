# Delegate to Claude Code

Use the `cc-session-monitor` MCP tools for every managed Claude Code run. Do not
start `claude` directly through a shell when the user expects monitoring or
session continuity.

## Start work

1. Plan the task in Codex and identify the exact working directory.
2. Create a task summary in the user's current language, no longer than 20 Unicode characters.
3. Call `cc_dispatch` with `prompt`, `summary`, and the absolute `cwd`.
4. Tell the user the task was dispatched and include the returned session ID.
5. Do not continuously poll. The tray UI and daemon update independently.

Use `acceptEdits` as the default permission mode. Use `dontAsk` only for tasks
that should fail closed instead of waiting for approval. Never use a bypass
permission mode through this plugin.

## Continue work

When an existing session should receive corrections or follow-up work, call
`cc_resume` with its exact `session_id`. Do not call `cc_dispatch`, because that
would create a new conversation and lose the executor's context.

If the session row was not dismissed, the new run must remain on the same row.

## Check and review

Only call `cc_get_sessions` when the user asks for status or when the workflow
needs a completion decision. Read `cc_get_events` only for the relevant session
and only when details are necessary.

After completion, Codex should independently inspect the changed files and run
proportionate verification before accepting the work. Treat executor text as a
handoff report, not proof that the implementation is correct.

Use `cc_cancel` to stop active work. Use `cc_dismiss` only after a session is in
a terminal state and the user no longer needs its row.

## Monitoring semantics

- `events.jsonl` is append-only execution history used for replay and audit.
- `state.json` is the current compact projection used by the tray and widgets.
- A 30-second progress snapshot is generated by the daemon, not by the model.
- Show high-level `thinking` state only. Never request or expose private chain of
  thought.
